# 天气数据接入

MainUI 使用 `ESP通信README.md` 中的精简缓存协议。保留原有字体、图标位置和今/明/后三日布局；降水总量按要求放在 `2h` 右边 `(328,172)`。

| API | 必需业务字段 | 显示方式 |
| --- | --- | --- |
| current | 字符串 temp、humidity、icon | 原位置显示温度、湿度及 32px 图标；数值四舍五入到整数 |
| daily3d | count=1～3；items 中 date、数值 temp_max/temp_min、text、icon | 按日期顺序填入今/明/后，显示最高/最低整数温度及 16px 图标；缺少的天显示占位符 |
| alert | count；items 中 id、title、type、type_name、severity_color | 使用第一条预警的 type 图标、type_name 和颜色；英文颜色转中文，文本最多 32px；count 可大于本帧条数 |
| minutely5m | start_time、interval_minutes=5、count=24、precip[24]、total_precip | 2 小时、24 个连续五分钟累计降水量；总量直接使用 mm，不换算成每小时雨强 |

所有缓存要求匹配的 api 和 `valid=true`。首次成功前显示 `--` 占位符；各 API 独立更新。无效 JSON、缺字段、错误类型、重复字段、无效日期、非法数值和总量不符均保留对应 API 的旧值。日期和降水时间戳会校验格式，降水时间戳必须带时区。日预报必须按日期递增；分钟数据的原始时间连续性由 ESP 校验。

`count=0,items=[]` 清除旧预警。预警 type 在资源包中不存在时，在原图标位置绘制通用警示符；天气图标缺失显示 `?`。每次绘制先清理天气内容区，避免短文本、零降水和无预警残留旧像素。

降水图向上收紧：细边框位于 (252,192)，大小 140×34px；内部从 x=253 起，将 138px 宽度分配给前 18 个五分钟点（90 分钟），每柱宽 7～8px，底边 y=225，最大高度 32px。下方 y=228 标出 0、30、60、90 分钟刻度；y=248 显示描述，文字底部在一言分隔线 y=266 之前。柱高按前 18 点最大值归一化，表示可见时段的相对变化；非零点至少 1px，零点留白。全零时总量显示 `0.0mm`，框内留白；尚无数据时显示 `--mm`，同样保留空框和时间刻度。总量通常保留一位小数，大于等于 99.95mm 显示整数，小于 0.05mm 的正数显示 `<0.1mm`，大于 9999mm 显示 `>9999mm`。

图表只显示前 90 分钟，顶部 `2h`、总量和描述仍使用完整 24 点、两小时数据。描述由降水数组生成，含数字在内最多 9 个字符，不使用可能较长的 API summary，不需要新增协议字段：

- 无有效数据：「暂无降水数据」。
- 全部为零：「未来两小时无降水」。
- 首次降水在稍后：如「30分钟后有降水」，取首个非零点的区间起点。
- 从首点起连续两小时非零：「两小时持续降水」。
- 当前有雨、停止后不再出现：如「45分钟后降水停」，取首个零点的区间起点。
- 当前有雨、停止后再次出现：「两小时内间歇降水」。

描述在 y=248 按实际字宽居中于 140px 图表区域，汉字按 16px、数字按 8px 计算。时间精度为五分钟预报区间，不代表实测的精确起止时间。即使降水只在最后 30 分钟出现，也会体现在两小时总量和描述中。

## 手动联调

依次执行，每条完成后再发下一条；可用 `api_result` 查看 succeeded/failed：

```text
api_refresh current
api_refresh daily3d
api_refresh alert
api_refresh minutely5m
```

完整流程成功并取得有效 RSP_CACHE 后，主循环更新天气模型。内容未变化不重刷；变化的数据进入待显示状态。API 请求忙碌期间不触发天气自动刷新，距上次显示/休眠结束至少 5 秒才显示，等待期间合并收到的天气结果。这是显示间隔下限，不是每 5 秒联网请求，也不是必须等四个接口齐全才显示。

天气仍使用 **初始化 → 整屏刷新**。本地时钟运行时保留控制器底图，供随后分钟变化时局刷右上角；未校时则刷新后休眠。单次局部刷新验证命令仍独立使用，详见 [时钟接入](CLOCK_README.md)。刷新失败不立即循环重试并提示 `use ref_epd to retry`；可用 `ref_epd` 重新显示已接受的数据，时钟运行时也会在下次分钟变化时按失效基准全刷恢复。

`esp_cache` / `esp_refresh` 只用于原始通信调试，不自动更新 UI。现有一言成功后的即时刷新、手动 `ref_epd` 不受天气 5 秒等待限制，但会同时显示已接受的天气数据并消耗待显示状态。时间已接入启动校时和 TIM10 走时，待办仍沿用示例内容。

## 验证范围

本机测试覆盖业务解析、失败保留旧数据、原位置绘制、总量位置、前 90 分钟的 18 根连续柱、零降水清理、缺图标回退、请求忙碌、重复结果抑制、合并显示、计时回绕和显示失败停止重试，命令见 [MainUI 测试](../tests/main_ui/README.md)。

本机测试使用显示替身，不验证 ESP 真实联网、外部 Flash 字模/图标或墨水屏实际效果；固件编译成功后仍需上板验证。
