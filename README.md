# TopInfo Project Notes

This file is the project handoff memory for the next Codex run.

## Project Summary

TopInfo is an STM32F401RCTx embedded project generated from STM32CubeMX and built with CMake/CLion. The current firmware drives:

- a 400x300 e-paper display through SPI1
- an external SPI Flash through SPI2
- an ESP module through USART2
- a LetterShell debug console through USART1
- USB CDC device support generated by CubeMX

The project mixes CubeMX-generated C code with custom C/C++ modules. Keep custom code inside `USER CODE` sections when editing CubeMX-owned files unless there is a clear reason not to.

## Build Notes

The root CMake files are:

- `CMakeLists.txt`
- `CMakeLists_template.txt`

The project uses `arm-none-eabi-gcc` and `arm-none-eabi-g++`. Custom include/source directories are explicitly listed in both CMake files. When adding a new module directory, update both files.

At the time this file was written, this shell environment did not have `cmake` or `make` in PATH, so builds could not be verified here. CLion has previously produced artifacts under `cmake-build-debug/`.

## Main Runtime Flow

Entry point: `Core/Src/main.c`.

The global flag `flash_rw` selects one of two runtime paths:

```c
uint8_t flash_rw = 0;
```

When `flash_rw == 0`, the default path runs:

```text
EPD_HW_Init()
EPD_HW_Clear()
shell_Init()

while (1) {
    EspCom_Poll();
    shellTask(&shell);
}
```

When `flash_rw == 1`, the Flash write/test path runs:

```text
EPD_Flash_Init()
EPD_Flash_Test()
Uart_Init_DMA()

while (1) {
    UART_DMA_Poll();
    Uart_OTA_Rx();
}
```

`EspCom_Init()` is currently called before the branch and starts USART2 interrupt receive.

## Flash Address Plan

Font offsets are defined in `Disp/Inc/Font.h`:

```text
FONT_GBK16_OFFSET      0x00000000
FONT_GBK24_OFFSET      0x000BC040
FONT_ASCII16_OFFSET    0x002630D0
FONT_ASCII24_OFFSET    0x002636C0
```

QWeather icon package base:

```text
0x00265000
```

Defined as:

```c
#define QWEATHER_ICON_FLASH_BASE 0x00265000UL
```

OTA/Flash write starts at:

```c
volatile uint32_t Flash_Write_Addr = 0x265000;
```

That means the USART1 OTA writer currently targets the QWeather icon area. Be careful before using `flash_rw == 1`; it may overwrite the icon package.

## ESP USART2 Protocol

ESP communication files:

```text
FIFO/Inc/Esp_Com.h
FIFO/Src/Esp_Com.c
ESP通信README.md
```

USART2 settings:

```text
Baudrate: 2000000
8N1
No flow control
PA2 USART2_TX -> ESP RX
PA3 USART2_RX <- ESP TX
```

Handshake/reset GPIO:

```text
PB0 STM32_Ready -> ESP input
PB1 ESP_Ready   <- ESP output
PA8 ESP_RST     -> ESP reset
```

Frame format:

```text
AA 55 VER TYPE SEQ LEN_H LEN_L PAYLOAD CRC_H CRC_L
```

Protocol details:

```text
VER = 0x01
CRC = CRC16-CCITT, seed 0xFFFF
CRC range = VER through PAYLOAD, excluding AA55 and CRC itself
Max payload = 384 bytes
```

STM32 commands:

```text
0x01 PING
0x02 GET_STATUS
0x03 GET_CACHE
0x04 REFRESH_API
0x05 READ_API
```

ESP responses:

```text
0x81 PONG
0x82 STATUS
0x83 CACHE
0x84 ACK
0x85 ERROR
```

Receive flow:

```text
USART2 byte interrupt
  -> HAL_UART_RxCpltCallback()
  -> EspCom_UartRxCpltCallback()
  -> internal RX FIFO
  -> EspCom_Poll()
  -> frame parser
```

The HAL UART complete callback lives in `FIFO/Src/Uart_RTX.c`, not in `usart.c`.

## USART1 OTA / Flash Write

Files:

```text
FIFO/Src/Uart_RTX.c
FIFO/Src/Uart_OTA.c
FIFO/Inc/FIFO.h
FIFO/Src/FIFO.c
```

USART1 DMA receive writes into `Fifo_Uart_Rx`. `Uart_OTA_Rx()` parses this frame format:

```text
55 AA LEN_H LEN_L PAYLOAD CRC_H CRC_L
```

CRC is Modbus CRC16 over:

```text
LEN_H LEN_L PAYLOAD
```

On valid frame:

```text
erase 4 KB sector when Flash_Write_Addr % 4096 == 0
write payload to Flash_Write_Addr
Flash_Write_Addr += 256
reply 55 AA 01
```

Current payload length limit in parser:

```text
0 < OTA_Data_Len <= 512
```

Important: the writer increments by 256 regardless of actual payload length.

## Known Issues / Watch Items

- `FIFO/Inc/FIFO.h` declares `Fifo_Init()`, but `FIFO/Src/FIFO.c` implements `FIFO_Init()`. Current code does not call it, so runtime is unaffected, but calling `Fifo_Init()` will link-fail.
- `Fifo_Uart_Rx` is global and zero-initialized in `main.c`; it is not explicitly initialized in the default path.
- `flash_rw == 1` writes starting at `0x265000`, which is also the QWeather icon package base.
- `CMakeLists.txt` and `CMakeLists_template.txt` both need updates for new custom directories.
- Many CubeMX generated files are already modified. Avoid broad rewrites.
- The repository may have a dirty worktree with user changes; do not revert unrelated changes.

## Recent Additions

The newest custom module is `QWeather/`, used to read and draw QWeather weather icons from external Flash. It follows the same project style as `Flash/`, `FIFO/`, and `Disp/`: headers in `Inc`, implementation in `Src`, and explicit CMake registration.
